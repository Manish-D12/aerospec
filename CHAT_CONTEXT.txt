BACKEND (backend/, Node >= 20, ESM, Express 5, Socket.io 4, pg, dotenv, mqtt):
  src/config.js            reads all env through dotenv
  src/db.js                pg.Pool (max 10). SSL is off for localhost and on otherwise
                           (DB_SSL overrides). initSchema() runs db/schema.sql.
                           connectWithRetry() retries every 10 s plus a watchdog.
                           withDbFallback(), isConnectionError(), withTransaction().
                           pool.on('error') is handled so the process never crashes.
  src/app.js               createApp(): cors({origin: CORS_ORIGIN}), express.json, routes,
                           notFound handler, error middleware
  src/server.js            http server + Socket.io on the same port. Runs MQTT if
                           MQTT_URL is set, otherwise the simulator. Graceful shutdown.
  src/routes/health.js     GET /health (db up/down plus feed stats)
  src/routes/sensors.js    GET/POST /api/v1/sensors, GET/PUT/DELETE /api/v1/sensors/:id,
                           GET /api/v1/sensors/:id/history?metric=&hours=
  src/repositories/sensorRepo.js     Postgres, with an in-memory fallback when the DB is down
  src/repositories/telemetryRepo.js  batch insert via UNNEST arrays; time-bucketed
                                     history (<= 360 points, AVG/MIN/MAX)
  src/realtime/simulator.js  RF model: RSSI random walk with fades, SNR vs noise floor,
                             10 spectrum bands, frequency = busiest band
  src/realtime/feed.js       ingest path: 60-frame backlog → io.emit('telemetry') → persist
  src/realtime/frames.js     validation for MQTT payloads
  src/realtime/mqttBridge.js optional; lazy import('mqtt')
  src/middleware/errorHandler.js   JSON {error:{status,message,details}}
  src/httpError.js, src/metrics.js (metric whitelist: rssi, frequency, snr)
  db/schema.sql            sensors, telemetry(id, sensor_id, metric, value, ts),
                           index (sensor_id, metric, ts DESC), default sensor 1
  db/seed.sql              generate_series: 24 h × 1-minute × 3 metrics for sensor 1
  scripts/seed.js          npm run seed (same RF model, transaction, --hours N)
  test/api.test.js, test/realtime.test.js   node:test + supertest
  eslint.config.js, .env.example, .gitignore

Socket.io events (server → client):
  'telemetry'          one frame per second:
                       { sensor_id, ts, source, readings:[{sensor_id, metric, value, ts} ×3],
                         spectrum[10], active_band }
  'telemetry:backlog'  the last ≤ 60 frames, sent on connect

Key decisions (request #1):
- One frame per second whose readings[] are exactly {sensor_id, metric, value, ts},
  instead of 3 separate events.
- Added a `sensors` table so CRUD has a real resource. Sensor 1 (the simulator)
  cannot be deleted (409). DELETE removes a sensor plus its telemetry in a transaction.
- History is downsampled into buckets (bucket_seconds is returned in the response).
- Broadcast happens before persisting, so the DB never delays the live view.
- No axios at that point (native fetch with a typed wrapper).

3. REQUEST #3 — REAL AUTHENTICATION (sent twice, the 2nd time shorter; same scope)
----------------------------------------------------------------------
Rules: Postgres + bcrypt + JWT + Resend. No demo or seeded users, no bypass.
Don't touch sensors, history, Socket.io or the simulator.

Backend (installed bcrypt 6, jsonwebtoken 9, resend 6):
- db/schema.sql: users(id SERIAL PK, name, email UNIQUE, password_hash,
  verified BOOLEAN DEFAULT false, created_at TIMESTAMPTZ DEFAULT now()).
- src/auth/tokens.js:
  - session JWT HS256 {userId, email}, 7d, iss=aerospec-api, aud=session
  - verify JWT {userId}, 24h, aud=email-verify (the two are not interchangeable)
- src/auth/mailer.js: Resend send. Without RESEND_API_KEY, or if Resend fails,
  the full link is logged to the console instead. Never throws.
- src/middleware/requireAuth.js: Bearer → req.auth or 401.
- src/repositories/userRepo.js: parameterized SQL; password_hash is never returned
  to clients.
- src/routes/auth.js, mounted at /api/v1/auth:
    POST /register            201 {token,user}; 400 validation; 409 duplicate; 503 DB down
    POST /login               200 {token,user}; 401 (same message for unknown email and
                              wrong password; dummy-hash timing equaliser)
    GET  /me                  200 {user}; 401 missing/invalid/expired token or deleted user
    POST /resend-verification 202 {sent,via}; 200 if already verified
    GET  /verify?token=       302 → APP_URL/login?verified=1
                              (failure: ?verified=0&reason=expired|invalid)
- Emails are lower-cased; passwords must be 8+ characters and ≤ 72 bytes.
- config.js: JWT_SECRET (if missing, a random secret is generated plus a warning),
  RESEND_API_KEY, EMAIL_FROM, APP_URL, API_PUBLIC_URL.
- A generated JWT_SECRET was written into the local backend/.env.
- test/auth.test.js: 17 tests (DB-only ones skip without Postgres).
- CI: added JWT_SECRET + APP_URL env to the backend job.

Frontend (installed axios):
- src/lib/authApi.ts: axios client, errors → ApiError.
- src/context/authContextValue.ts (context + AuthContextValue interface),

4. HOW TO RUN
----------------------------------------------------------------------
Terminal 1 (backend, http://localhost:4000):
  cd backend
  cp .env.example .env        (already exists locally; set DATABASE_URL / JWT_SECRET)
  npm install
  npm run seed                (tables + 24 h history; optional)
  npm run dev

Terminal 2 (frontend, http://localhost:5173):
  cd frontend
  cp .env.example .env.local  (already exists locally)
  npm install
  npm run dev

Then register an account at /register (there are no demo accounts). Without
RESEND_API_KEY, the verification link is printed in the backend console.

Pure-SQL seed alternative:
  psql "<DATABASE_URL>" -f backend/db/schema.sql -f backend/db/seed.sql

Checks:
  cd backend && npm run lint && npm test
  cd frontend && npm run build && npm run lint
